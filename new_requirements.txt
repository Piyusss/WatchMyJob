# 3. SUPPORT MULTIPLE LOCATIONS

The current implementation allows only one location. Change this.

A user must be able to select multiple locations.

Example:

```text
India
 ├── Karnataka
 │    └── Bangalore
 └── Maharashtra
      └── Pune
```

The user should be able to select:

```text
✓ Bangalore
✓ Pune
```

and both must be saved.

### UX

After selecting a location, show it as a removable selection/chip:

```text
Bangalore   ×
Pune        ×
```

The user can then add another location.

### Important

A location should represent the complete hierarchy:

```text
Country + State/Region + City
```

Do not store only `"Pune"` or `"Bangalore"` because city names can exist in multiple regions.

Prefer a canonical representation such as:

```text
{
  country: "IN",
  state: "MH",
  city: "Pune"
}
```

or equivalent normalized database identifiers.

### Matching behavior

The backend job-matching logic must treat multiple selected locations as **OR**, not AND.

For example:

```text
User locations:
Pune
Bangalore
```

means:

```text
Pune OR Bangalore
```

not:

```text
Pune AND Bangalore
```

Also ensure that changing or removing one location does not affect the others.
